## 项目背景

小米摄像头（或带 SD 卡/联动存储的摄像头）会把录像按**约 19 分钟一段**切成大量 `.mp4` 小分段，持续写入 NAS 共享文件夹。由此带来三个痛点：

| 痛点 | 说明 |
| --- | --- |
| 文件数量庞大 | 单点位每天产生 150+ 个分段，几天就堆积上千个文件 |
| 回放困难 | 每段仅 19 分钟，查看历史录像需逐个点开 |
| 管理混乱 | 文件平铺在摄像头目录下，无法按时间线检索 |

本项目在 NAS 上以 **Docker 容器**方式运行一个轻量 Go 程序，自动完成「**分组合并 → 按时归档 → 删除源文件**」的完整流程，并把合并任务挂到群晖「任务计划」，实现**全自动无人值守**。

---

## 功能特性

- ✅ **双通道分别合并**：`XiaomiCamera_01_xxx` 下的 `0`（主码流）与 `1`（副码流）是两个独立通道，分别合并、分别命名，绝不混流；单码流平铺目录自动识别为单通道。
- ✅ **每 10 段一组智能合并**：按时间顺序每 10 个分段合并成一个视频（`GROUP_SIZE=10`）；最后一组不足 `MIN_GROUP_SIZE=8` 段时**等待下次运行积攒**，避免产生零碎小文件。
- ✅ **按年月日自动归档**：输出到 `merged/<年>/<月>/<日>/`，文件名即时间线（组内首段开始时间 + 通道短名），回放一目了然。
- ✅ **合并成功自动删除源文件**：释放磁盘空间，不重复占用。
- ✅ **定时自动运行**：可在群晖任务计划中配置每天任意时段自动触发（示例：00:00 / 12:00 / 20:00）。
- ✅ **防重叠、防重复**：脚本级 `docker ps` 防重叠 + 程序级「输出已存在则跳过」+ 删源机制，三重保障绝不重复备份。
- ✅ **轻量多架构镜像**：两阶段构建，最终镜像仅 ~100MB；支持 `linux/amd64`（Intel/AMD 群晖）与 `linux/arm64`（ARM 群晖）。
- ✅ **全中文注释**：源码、Dockerfile、编排文件均含详细中文注释，附完整《部署与操作文档》。

## 工作原理

```
小米摄像头 ──联动写入──▶ NAS /volume1/CCTV
                            │
                            ▼
            ┌─────────────────────────────┐
            │   Docker 容器（一次性任务）      │
            │  xiaomi-camera-merge:local    │
            │                               │
            │  1. 扫描摄像头目录结构           │
            │  2. 识别单元（平铺/双通道）       │
            │  3. 按开始时间排序，每 10 个一组  │
            │  4. 不足 8 个 → 等待下次积攒      │
            │  5. ffmpeg 无损合并（copy 流）   │
            │  6. 输出 merged/<年>/<月>/<日>/ │
            │  7. 删除已合并的源文件           │
            └─────────────────────────────┘
                            │
                            ▼
             群晖「任务计划」定时拉起容器
             （每天 00:00 / 12:00 / 20:00）
```

- **单元（Unit）识别**：扫描摄像头目录时自动区分「平铺单通道」（如 `XiaomiCamera_00_xxx`，短名 `00`）与「双通道」（如 `XiaomiCamera_01_xxx/0`、`/1`，短名 `01_0` / `01_1`）。
- **合并方式**：调用 `ffmpeg` 以 `-c copy` 方式无损合并（不重新编码，速度快、画质无损失）。
- **运行方式**：容器设计为**一次性任务**，运行完自动退出，不常驻占用内存；定时拉起由群晖任务计划负责。

## 快速开始（Docker）

### 方式一：docker compose（推荐，含完整配置）

```bash
git clone https://github.com/1272095268/xiaomi-camera-merge.git
cd xiaomi-camera-merge

# 构建镜像并运行一次（一次性任务，运行完容器自动退出）
docker compose up --build
```

### 方式二：手动 docker build / run

```bash
docker build -t xiaomi-camera-merge:local .

docker run --rm --name xiaomi-camera-merge \
  -e TZ=Asia/Shanghai \
  -e DELETE_SUCCESS=true \
  -e MAX_MERGE=0 \
  -e VIDEO_EXT=mp4 \
  -e MIN_AGE_MIN=30 \
  -e SKIP_CURRENT=true \
  -e GROUP_SIZE=10 \
  -e MIN_GROUP_SIZE=8 \
  -v /volume1/CCTV:/app/video \
  xiaomi-camera-merge:local
```

> 将 `/volume1/CCTV` 替换为你实际的录像存储目录。

### 方式三：群晖 Container Manager（图形化）

1. 打开 **Container Manager → 项目 → 新增**；
2. 选择「从路径创建」，指定项目目录（含 `docker-compose.yml` 的目录）；
3. 确认配置后点击「构建」；构建成功后容器会自动运行一次合并任务。

## 环境变量说明

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TZ` | `Asia/Shanghai` | 时区，保证「当前小时」判断与归档路径正确 |
| `DELETE_SUCCESS` | `true` | 合并成功后删除已合并的源文件（释放空间） |
| `MAX_MERGE` | `0` | 单次最多合并组数；`0` = 不限制 |
| `VIDEO_EXT` | `mp4` | 待合并文件的扩展名 |
| `MIN_AGE_MIN` | `30` | 修改时间不足 30 分钟的文件不处理（防文件写入中） |
| `SKIP_CURRENT` | `true` | 跳过开始时间处于当前小时的文件（防写入中） |
| `GROUP_SIZE` | `10` | 每组合并的分段数量（v3.0，「10 个左右一合并」） |
| `MIN_GROUP_SIZE` | `8` | 最后一组不足该数量则等待下次积攒 |

├── 2026/
│   ├── 09/
│   │   ├── 01/
│   │   │   ├── 20260901191847_00.mp4      # 平铺单通道（短名 00）

- 目录：`merged/<年>/<月>/<日>/`
- 文件名：`<组内首段开始时间(14位)>_<通道短名>.mp4`
  - 平铺单通道：`00`
  - 双通道：`01_0`（主码流）/ `01_1`（副码流）
- 排序即时间线，按天浏览历史录像非常直观。

## 群晖 NAS 定时任务配置

程序本体是**一次性任务**，定时自动运行依赖群晖「任务计划」：

1. 打开 **控制面板 → 任务计划 → 新增 → 计划的任务 → 用户定义的脚本**；
2. 常规：任务名称 `xiaomi-camera-merge-task`，用户 `root`；
3. 计划：按需设置每天运行时间（示例 00:00 / 12:00 / 20:00）；
4. 任务设置：粘贴 [`synology-task-scheduler.sh`](synology-task-scheduler.sh) 的内容并保存。

脚本内置**防重叠保护**：若已有合并容器在运行（如积压较多时耗时较长），本次调度自动跳过，避免两个进程同时读写同一批文件。

## 手动运行

任何时刻想立即执行一次合并：

- **群晖任务计划**：选中对应任务 → 点击顶部「**运行**」按钮；
- 或命令行直接 `docker run`（见[快速开始](#快速开始docker)）。

## 防重复机制

| 层级 | 机制 | 效果 |
| --- | --- | --- |
| 脚本级 | `docker ps` 检测已有容器则跳过 | 防止任务重叠 |
| 程序级 | 输出文件已存在则跳过该组 | 防止重复合并 |
| 数据级 | 合并成功后删除源文件 | 源文件不残留，杜绝重复备份 |

三重保障叠加，即使多个定时任务同时触发，也不会产生重复输出。

## 运行日志

每次运行都会在 `CCTV/xiaomi-video-merge-log/` 下生成日志文件：

```
20260922_151303.log   # 命名：YYYYMMDD_HHMMSS.log
```

日志记录：配置回显、单元识别、分组情况、跳过原因（不足一组）、合并结果、删源数量、总计统计（成功/失败/跳过组数），便于排查与审计。

## 常见问题（FAQ）

**Q1：为什么最后一组只有 5 个文件却不合并？**
这是预期行为：最后一组不足 `MIN_GROUP_SIZE`（默认 8）个时，程序会跳过并等待下次运行积攒，凑够 8 个才合并，避免产生零碎小文件。

**Q2：合并后源文件会被删除吗？**
会。`DELETE_SUCCESS=true` 时，合并成功的源分段会被删除以释放空间。如不需要此行为，将其改为 `false`。

**Q3：双通道会不会被混在一起？**
不会。`XiaomiCamera_01_xxx` 下的 `0` 与 `1` 是独立单元，分别排序、分别合并、分别命名（`01_0` / `01_1`）。

**Q4：容器为什么跑完就退出？**
这是设计使然：一次性任务容器，运行完自动退出，不常驻占用内存；定时拉起由群晖任务计划负责。这是资源占用最小的方案。

**Q5：是否支持 ARM 群晖（如 DS220+ 等）？**
支持。Dockerfile 采用多阶段构建，可交叉编译 `linux/arm64` 与 `linux/amd64`。

**Q6：可以改成每小时/每 30 分钟运行吗？**
可以。在群晖任务计划中调整计划时间即可；程序本身是幂等的，多跑不会产生重复输出。
